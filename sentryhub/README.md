# SentryHub

A scalable, YouTube-style app for sharing Tesla **Sentry Mode / Dashcam** footage.
Built so the alpha runs on the same architecture as production — no re-platforming
to reach beta or live.

**Stack:** Next.js 14 (App Router) · Supabase (Auth + Postgres + RLS) · **Mux**
(video, behind a provider abstraction) · Resend (email) · Web Push (VAPID).
See [`ARCHITECTURE.md`](ARCHITECTURE.md) for the design and data-flow diagrams.

## Features

- **Accounts & profiles** — email/password auth, auto-created profile, public profiles.
- **Upload & playback** — resumable direct-to-Mux upload, automatic transcode to
  adaptive HLS, CDN delivery, auto thumbnails, atomic view counts.
- **Feed & search** — newest-first grid (ready videos only), text search, tag filter.
- **Tag taxonomy** — categories: *Event type, Severity, Setting, Camera angle*.
- **Social** — optimistic likes, comments.
- **Notifications** — in-app **+ email + web push**, generated by DB triggers:
  - `new_video` — a video you follow a tag of becomes ready
  - `comment` — someone comments on your video
  - `like` — someone likes your video
- **Preferences & subscriptions** — toggle each notification type, follow/unfollow tags,
  enable push per device.
- **Moderation** — users can report videos and comments; staff get an `/admin`
  review queue to remove content or dismiss reports. Removed content is hidden at
  the database (RLS), not just in the UI.
- **Roles & feature flags** — three roles (`user` / `moderator` / `admin`) plus
  per-user entitlements that override role defaults. Access is gated in the UI
  *and* enforced by RLS + a role-escalation guard trigger.
- **Dashboards** — every creator gets `/dashboard` (their videos + views, watch
  time, likes, comments). Staff get `/admin` (moderation + platform analytics);
  admins also get Users & roles and Ads management.
- **House ad system** — admin-managed campaigns and ads placed in `feed`,
  `sidebar`, or `preroll` slots, weighted and optionally tag-targeted, with the
  per-user `no_ads` entitlement respected. Impressions and clicks are tracked.
- **Event analytics** — an append-only `events` table (views, watch progress, ad
  impressions/clicks) aggregated by SQL RPCs and surfaced on the dashboards.

## Roles & access control

Roles are stored on `profiles.role`. To make the first admin, sign up then run in
the Supabase SQL Editor:

```sql
update public.profiles set role = 'admin' where username = 'your_username';
```

After that you can manage all other users' roles and feature entitlements from
**Admin → Users & roles** — no more SQL needed. Nav links appear by role:
Dashboard (everyone signed in), Mod/Admin (staff). Feature flags are seeded in
`schema.sql` (`upload`, `comment`, `live_stream`, `beta`, `no_ads`); add more there.

## Prerequisites

- Node.js 18.18+ (or 20+)
- Free accounts: [Supabase](https://supabase.com), [Mux](https://mux.com),
  and (optional for email) [Resend](https://resend.com)

## Setup

### 1. Install

```bash
npm install
```

### 2. Database

Supabase dashboard → **SQL Editor** → paste [`supabase/schema.sql`](supabase/schema.sql) → **Run**.
Creates tables, RLS, triggers, and seeds the tag taxonomy.

### 3. Environment

```bash
cp .env.local.example .env.local
npm run gen:vapid     # prints VAPID keys to paste in
```

Fill in `.env.local`:

- **Supabase** — URL, anon key, and **service role key** (Settings → API).
- **Mux** — `MUX_TOKEN_ID` / `MUX_TOKEN_SECRET` (Settings → Access Tokens, with
  Video permissions) and `MUX_WEBHOOK_SECRET` (Settings → Webhooks).
- **VAPID** — from `npm run gen:vapid`.
- **Resend** — `RESEND_API_KEY` (optional; email is skipped if absent).
- **NOTIFY_WEBHOOK_SECRET** — any long random string.

### 4. Mux webhook

Mux dashboard → **Settings → Webhooks** → add endpoint:

```
https://YOUR_DOMAIN/api/webhooks/mux
```

Copy its signing secret into `MUX_WEBHOOK_SECRET`. For local dev, expose your
machine with a tunnel (e.g. `ngrok http 3000`) and use that URL.

### 5. Notification delivery webhook

Supabase dashboard → **Database → Webhooks** → create webhook:

- Table: `public.notifications`, Events: **Insert**
- Type: **HTTP Request**, Method **POST**
- URL: `https://YOUR_DOMAIN/api/webhooks/notification`
- HTTP header: `x-webhook-secret: <your NOTIFY_WEBHOOK_SECRET>`

(Locally, point it at your tunnel URL.)

### 6. Auth redirect

Supabase → **Authentication → URL Configuration** → add
`http://localhost:3000/auth/callback` (and your prod URL). For quick testing you
can disable "Confirm email" under Authentication → Providers → Email.

### 7. Run

```bash
npm run dev
```

→ http://localhost:3000

> Note: web push requires HTTPS in production (localhost is exempt). Add
> `public/icon-192.png` for the push/app icon.

## Switching video providers later

The app is provider-agnostic. To move to Cloudflare Stream you only implement
the four methods in `src/lib/video/cloudflare.ts` and set `VIDEO_PROVIDER=cloudflare`
— no other code changes. (Existing videos would need re-ingesting; new uploads
just work.)

## Project structure

```
supabase/schema.sql              # tables, RLS, triggers, seed taxonomy
scripts/gen-vapid.mjs            # VAPID keypair generator
public/sw.js                     # web push service worker
src/
  middleware.ts                  # refreshes the auth session cookie
  lib/
    supabase/{client,server,middleware,admin}.ts
    video/{provider,mux,cloudflare,index}.ts   # provider abstraction
    notify/{messages,email,push}.ts            # delivery
    types.ts  format.ts
  components/                    # Navbar, Auth, Upload, VideoPlayer, Like, Comments,
                                 # Notification*, Tag*, PushToggle, ...
  app/
    page.tsx                     # feed + search + tag filter
    login/  signup/  auth/callback/
    upload/                      # resumable upload form
    watch/[id]/                  # Mux player + likes + comments
    profile/[username]/
    notifications/  settings/
    api/
      upload/create/             # create row + Mux direct upload
      webhooks/mux/              # asset ready -> mark ready (fires alerts)
      webhooks/notification/     # fan out email + push
      push/subscribe/            # store a device subscription
```

## Deploy (Vercel)

Import the repo into Vercel, add all env vars from `.env.local`, set
`NEXT_PUBLIC_APP_URL` to your domain, and update the Mux + Supabase webhook URLs
and Supabase auth redirect to the production domain.
